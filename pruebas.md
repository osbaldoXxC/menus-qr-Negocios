Bloque 1: Integridad del Backend (Funcional)El objetivo es verificar que la lógica de negocio en Node.js y la persistencia en PostgreSQL sean correctas.Prueba de Aislamiento (ABAC):Acción: Inicia sesión con el Restaurante A. Intenta realizar una petición GET a las categorías del Restaurante B mediante su ID usando el token del Restaurante A.Resultado esperado: El servidor debe devolver 403 Forbidden o 401 Unauthorized.Prueba de Categorías y Reordenamiento:Acción: Crea 3 categorías ("Entradas", "Platos Fuertes", "Bebidas"). Cambia el orden enviando el PUT /api/categories/orden con el orden invertido.Resultado esperado: Al hacer un GET público, "Bebidas" debe aparecer primero y "Entradas" al final.Prueba de Pausado Lógico:Acción: Pausa un platillo (cambia activo a false) y recarga el menú público (/menu/:id).Resultado esperado: El platillo debe desaparecer instantáneamente del menú público pero seguir existiendo en el dashboard del dueño para futura activación.Bloque 2: Consistencia de Caché (Redis)Esta es la prueba crítica para garantizar rendimiento y datos actualizados.Prueba de Invalidación por Eventos:Acción:Carga el menú público (esto crea la caché en Redis).En el panel privado, edita el nombre de un platillo.Recarga inmediatamente el menú público.Resultado esperado: El menú público debe mostrar el nombre nuevo. Si muestra el anterior, significa que la función redis.del() no se ejecutó en el controlador de edición.Prueba de TTL:Acción: Configura un TTL corto (ej. 60 segundos). Espera ese tiempo tras una carga.Resultado esperado: La caché debe borrarse automáticamente y obligar al backend a leer de nuevo la base de datos (Postgres) en la siguiente petición.Bloque 3: Flujo de Simulación de IA (Frontend Demo)Aquí verificamos la experiencia del usuario (UX) para tu presentación.Prueba del Flujo de Descubrimiento:Acción: Accede a /no-sabes-que-comer.
