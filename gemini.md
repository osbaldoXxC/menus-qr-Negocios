MÓDULO PÚBLICO: DESCUBRIMIENTO Y COMENSALES (USER-FACING)Esta sección engloba las vistas accesibles por cualquier usuario sin necesidad de una cuenta de negocio. Se divide en dos flujos independientes: el comensal en sitio (vía QR) y el usuario indecisos (vía web).Flujo A: El Comensal en el Restaurante (Mesa)Ruta: /scannerFuncionamiento: Solicita permisos nativos de la cámara del dispositivo móvil. Actúa como un lector de códigos QR en tiempo real.Lógica: Al detectar un código QR válido de la plataforma, extrae el identificador único (restaurant_id) de la URL y ejecuta una redirección automática hacia la ruta del menú.Ruta: /menu/:restaurant_idFuncionamiento: La carta digital interactiva del establecimiento.Consumo de API: Realiza una petición GET /api/menu/:restaurant_id. El backend responde con los datos del restaurante, su configuración de marca y el catálogo de comida.Inyección Dinámica de Estilos (Branding): El frontend lee el JSON de respuesta y aplica en caliente el color_primario (en botones, bordes y tipografía destacados), el logo_url en la cabecera y el layout_type correspondiente:LISTA_SIMPLE: Vista compacta de texto y precio.CUADRICULA_FOTOS: Rejilla visual enfocada en las imágenes de los platos.TARJETAS_DETALLADAS: Tarjetas anchas con descripción completa e ingredientes.Renderizado Ordenado: Mapea el arreglo de categorías respetando estrictamente el orden numérico en el que vienen desde la base de datos. Los platillos pausados (activo: false) no se muestran, ya que el backend los filtra automáticamente.Flujo B: El Cliente Indeciso (Landing de Descubrimiento - Simulación de IA)Ruta: /no-sabes-que-comerInterfaz: Una landing page independiente y sumamente atractiva visualmente, diseñada para usuarios que no han decidido qué comer ni a qué lugar ir.Acceso: Cuenta con un botón discreto pero visible: "Iniciar sesión para Clientes". Requiere autenticación obligatoria mediante JSON Web Tokens (JWT) adjuntos en las cabeceras HTTP de cada petición.Ruta: /login (Sección Negocios)Formulario de credenciales corporativas (Email y Password). Al ser exitoso, almacena el token de acceso y redirige al panel privado.🏠 Pestana 1: Inicio / Resumen (Dashboard Principal)Módulo de Código QR (Prioridad Alta): Ubicado en la sección superior de la pantalla de forma prominente. Muestra el código QR del restaurante generado dinámicamente por el backend a través del endpoint GET /api/restaurants/qr.Acciones Directas:Botón "Ver QR" para ampliarlo en pantalla.Botón "Descargar QR" con opciones de formato (PNG de alta resolución / PDF listo para impresión de mesa).Botón "Copiar Enlace" para guardar en el portapapeles la URL pública de su menú (/menu/:id).Métricas Rápidas: Tarjetas informativas con contadores en tiempo real extraídos de la base de datos: cantidad de platillos actualmente activos y listado de promociones vigentes.🍔 Pestaña 2: Gestión de Menú (Estructura del Catálogo)Esta sección se subdivide internamente para otorgar control total sobre la oferta gastronómica.Sub-módulo de Categorías (Dinámicas y Personalizadas)CRUD Completo: Permite crear categorías ilimitadas (ej. Entradas, Bebidas, Cortes de Carne).Lista Ordenable (Drag and Drop): Implementación de interfaz interactiva para arrastrar y soltar. El usuario puede mover bloques para decidir visualmente el orden de su menú.Sincronización: Al soltar una categoría en una nueva posición, el frontend recalcula el índice numérico de la propiedad orden de todo el listado y dispara una petición PUT /api/categories/orden para actualizar de forma masiva las posiciones en la base de datos PostgreSQL.Validación de Borrado: El sistema prohíbe eliminar una categoría si esta cuenta con platillos enlazados, forzando al usuario a reubicarlos primero.Sub-módulo de Platillos (Productos)Formulario de Creación/Edición: Envía los datos como multipart/form-data al servidor.Campos Requeridos: Nombre, descripción, precio y selección de ingredientes.Componente Select Dinámico: El menú desplegable para asignar la categoría se nutre en tiempo real de las categorías creadas por el restaurante en el sub-módulo anterior.Gestión de Imagen: Espacio para arrastrar y soltar la fotografía del platillo. Pasa por el middleware de carga directo hacia el bucket de AWS S3.Pausado Lógico (Switch Toggle): Cada platillo listado en la tabla de administración posee un interruptor para modificar su disponibilidad (activo: true/false). Si se apaga, el platillo se oculta inmediatamente del menú público sin necesidad de eliminar su registro o perder su información histórica.🎨 Pestaña 3: Personalización y Diseño (Branding)Configuración Visual: Carga del logotipo del establecimiento y banners de cabecera.Paleta de Colores: Selector de color cromático para definir el color_primario de la interfaz pública.Selector de Layout: Botones de opción para elegir cómo se estructurará la carta digital (Lista, Cuadrícula o Tarjetas).Mockup de Celular (Live Preview): Un contenedor en pantalla que simula un dispositivo móvil y renderiza en tiempo real cómo impactan los cambios de color, logo y layout en el menú que verán sus comensales.3. REQUERIMIENTOS CRÍTICOS DEL BACKEND (PROCESAMIENTO Y CACHÉ)Para que el frontend funcione como se describe, el backend (Node.js/Express) implementa de manera estricta las siguientes directrices técnicas:Reglas de Control de Acceso e Aislamiento (ABAC / Multi-Tenant)Cualquier petición de mutación de datos (POST, PUT, DELETE) en el panel de administración pasa por el middleware de verificación de JWT.Validación Cruzada: Al crear o editar un platillo, el controlador del backend verifica mediante SQL que el categoria_id enviado en el cuerpo de la petición pertenezca genuinamente al restaurante_id autenticado en ese token. Un restaurante no puede inyectar productos en categorías de otro negocio.Consulta del Menú Público (GET /api/menu/:restaurant_id)La consulta SQL que alimenta la carta digital pública ejecuta de forma obligatoria un LEFT JOIN estructurado de la siguiente manera:SQLSELECT 
    c.id AS categoria_id, c.nombre AS categoria_nombre, c.orden AS categoria_orden,
    p.id AS platillo_id, p.nombre AS platillo_nombre, p.precio, p.descripcion, p.url_imagen
FROM categorias_restaurante c
LEFT JOIN platillos p ON c.id = p.categoria_id AND p.activo = true
WHERE c.restaurante_id = $1 AND EXISTS (
    SELECT 1 FROM restaurantes r WHERE r.id = $1 AND r.suscripcion_activa = true
)
ORDER BY c.orden ASC, p.nombre ASC;
